The dock floats clear of the screen edge, so the wallpaper carries underneath and no full strip of a 14-inch display is spent on chrome. A running application is marked by a single 4 px dot, not a bar. Clock and system state sit in their own tile rather than in a second panel across the top — the same information as macOS offers, without surrendering another row of pixels.

The part nobody else does

A Windows program running under Wine keeps Wine's 1995 chrome. It works perfectly and still looks like a visitor. We generate the Wine theme from the Plasma colour scheme, so it follows the desktop — including when you switch to dark.

Why blur is restricted. Mica behind every window looks wonderful and costs several watts on a 15 W processor. Battery life is a stated priority for this machine, so blur is spent where it is seen — the panel and menus you look at constantly — and withheld from window backgrounds, where it mostly renders wallpaper nobody is reading.

Same reasoning for 150 ms: fast animation reads as a responsive machine. Slow animation reads as a slow one, whatever the benchmark says.

No dock magnification. macOS's zoom-on-hover is the most imitated and least useful thing about its dock — it moves the target you are aiming at. Icons stay put; hover changes only the background.

What this actually costs

Configuration — days

  • Centred taskbar, panel height and grouping
  • Window radius, shadow, blur rules in KWin
  • Colour scheme and accent
  • Icon theme and cursor set
  • Selawik as the interface font
  • Wallpaper, boot splash, login screen, system name

Real work — weeks

  • Generating the Wine theme from the live colour scheme
  • Keeping it in sync when the user switches to dark
  • An icon set that covers Windows applications too, so a Wine app in the menu does not break the drawing style
  • Font rendering tuned inside Wine prefixes

The left column is what makes it stop looking like Aurora. The right column is what makes it look like one system rather than two.
